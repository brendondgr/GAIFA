# Setting up AIHub

How to install AIHub on a new machine, from a bare Linux install to every mod and model. It's written for the hardware AIHub is built on: an **AMD Strix Halo** (Ryzen AI MAX+ 395, Radeon 8060S, `gfx1151`) with 128 GB of unified memory, on **Fedora Linux**. Everything in the repository (the container images, the PyTorch wheels, the engines' settings) is built and tuned for that chip, so on that hardware these docs should be all you need.

**Other hardware.** The hub and the CPU-only mods (LLM Relay, OpenCode, Chat) run on any Linux with systemd. The GPU mods don't run elsewhere without changes: an NVIDIA or another AMD GPU needs its own images, wheels and model choices, which these docs don't cover. macOS and Windows aren't supported (AIHub runs on systemd user services).

| 3. The mods | one doc per environment, in the order in [hub.md](hub.md#installing-the-mods) | 10 min to an hour each | up to 15 GB each (images, runtimes) |
| 4. The models | one doc per model in [models/](models/): where to get it, its files and hashes, what to look for | the downloads | 354 GB for every model; most setups need far less |

You can stop after any mod. Each environment doc says which features need it; each model doc says which environment runs it.

## How these docs work

- **Environment docs** live in the mod they belong to, `services/<id>/setup/<env>.md`, so a mod's setup goes wherever the mod goes and disappears when it's deleted. Each one has the same sections: what it is, the versions tested, prerequisites, install, configuration, how to check it, what to look for, and known gaps. The format is in [mods.md §9](../mods.md#9-setup-docs).
- **Model docs** in [models/](models/) are generated from the models registry (`data/models/registry.json`) by `aihub docs`, and regenerated whenever a model is added, changed or removed, including models a mod downloads for you. The generated part (files, sizes, hashes, source, which environment and which workflows use it, the download command) sits between markers; the sections below it (**Where to get it**, **What to look for**, **Notes**) are written by hand and never overwritten.
- **`aihub docs --check`** fails when a generated part is out of date, a model has no environment, or a model has neither a recorded source nor a written "Where to get it". The test suite runs it, so the docs can't drift from the registry.
